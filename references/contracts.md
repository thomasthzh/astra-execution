# 任务包与状态契约

按需取用，不必每次生成全部模板。已有记录能表达信息时复用。示例是字段约定，不是授权或当前任务。

## 单一运行账本

```text
Run: 标识 / 最后更新时间 / 唯一调度者
Goal: 用户目标与完成终点
Context: 仓库绝对路径、目标分支、已核实 base SHA
Forge: github/gitlab/local、实例 Web/API 地址、项目路径与项目 ID
Authorization: 用户已授权的具体外部动作与目标；未知项单列
Acceptance: 可观察行为 → 必需检查/验收方式；优化指标另列
Budget: 用户限制（如有）；真实槽位；选定并发与理由

ID | 目标/验收 | 依赖 | owner/agent-id | worktree/写入资源 | 状态 | 产物/证据 | 下一步

Decisions: 触发事实 → 决定 → 影响范围（仅实质决定）
External: issue/PR/MR/pipeline/release ID、完整 URL、目标、最新已确认状态
Checkpoint: 正在进行的操作、待核对结果、恢复入口
```

先登记 owner 再分派。更换 owner 前确认旧 worker 停止写入或隔离其资源；失联不等于停止。依赖指向具体产物/合同，代码包含相应基线。注明用户已有修改归属，避免误纳入提交。

## 任务状态

| 状态 | 所需事实 | 正常后继 |
| --- | --- | --- |
| BACKLOG | 有目标，未具备分派条件 | READY / BLOCKED |
| READY | 验收明确、依赖可取、写入范围确定 | RUNNING |
| RUNNING | 已认领且在执行 | VERIFY / BLOCKED |
| VERIFY | 有产物，等待核对验收证据 | READY_TO_INTEGRATE / DONE / RUNNING |
| READY_TO_INTEGRATE | 验收通过且需要跨分支集成 | INTEGRATING |
| INTEGRATING | 唯一集成者持有候选版本 | DONE / RUNNING / BLOCKED |
| BLOCKED | 具体阻塞、解除条件与下一责任方 | 解除后回到合适状态 |
| DONE | 达到该任务指定终点，证据对应产物 | 需求或证据改变时重新打开 |

这是本地任务状态，不替代宿主 goal/automation 状态及其转换规则。任务终点须显式；研究/局部实现可在 VERIFY 后 DONE，但整体交付条件不能省略。

PR/MR、CI/部署另记事实，例如 `mr=opened, pipeline=pending, merged=false, deployed=false`。GitLab 记录实例 + project_id + issue/MR iid，不能跨项目仅靠 #12/!12 识别。用户要求发布而 CI 还在跑时，整个 run 不能标记完成。

## Worker 任务包

```text
角色：实现者（或只读调查者），仅负责任务 T…。
目标与验收：具体用户行为/接口及完成条件。
环境：仓库/worktree 绝对路径、base SHA、必要文件和已有事实。
依赖：已交付前置产物、合同与位置。
写入所有权：允许路径/资源；确需扩大范围先报告。
范围与授权：允许动作；任务之外建议单列。
验证：验收行为对应的检查；现有入口/命令（已知时）、结果与证据位置。
停止/升级条件：具体阻塞、重复失败或预算边界；带证据返回。
返回：摘要、实际修改路径、交付版本/差异、验证、未解决点。
```

不要求空泛长报告、复读计划、全仓扫描或重复询问已确定目标。短任务一个段落即可。

自动验证循环的失败分类、验收质量和可选结构化记录见 [verification.md](verification.md)。复用已有 CI/任务系统记录；没有自动消费者时，不为满足模板再造一份 JSON 账本。

## Lead 委派包（仅大任务队列）

```text
推进这一组目标到指定验收；你是任务状态唯一写入者。
已确定：目标、优先级、跨模块约束、授权、总并发预算。
负责：依赖、owner、分派与验收覆盖，日常技术问题自行处理。
升级：跨任务约束冲突、目标/验收变化、证据不足的关键权衡。
返回：已验收/正在做/阻塞、关键决定、待裁决问题与推荐。
worker 数取真实剩余槽位，不通过再开 lead 递归扩张组织。
```

## Worker 结果 / 集成交接

```text
Task: ID、owner、验收结论
Artifact: worktree、分支/commit SHA；未提交则列精确差异/文件
Changes: 改了什么、用户可见行为
Evidence: 检查命令/方式、结果、被检查提交及未提交增量、证据位置、失败/未运行项及原因
Next action: 未通过时的失败类别、下一假设或解除条件；通过则省略
Dependencies: 前置版本、接口影响、集成顺序
Risks: 尚未解除的具体问题（没有则省略）
External actions: 已发生动作与返回 ID；后续动作的当前授权
```

“已通过”须能定位证据。没跑 CI 就标未运行，局部测试不替代要求的集成检查。无 Git 用产物位置与版本描述，不为短期文档修改额外建哈希系统。

## 决策升级包

```text
Task / 决策：一句话
影响：阻塞哪些验收/下游任务
证据：可定位事实、实际失败、已排除假设
选项：A/B 的行为与代价，推荐一个并说明依据
所需回答：需要决定的具体约束/取舍
期间可继续：独立任务或可逆准备
```

无新证据不把问题换句话再问。明显可逆且符合已有意图的技术取舍自行决定，留短记录；需要用户决定的范围或权限不能由 Astra 凭空授权。

## 用户汇报

日常进度：结果/新发现 + 下一步将解决的不确定性。最终：产物链接、必要验证、重要决定、真实剩余限制。预算数据能归因才归因，估算不能报成事实。
